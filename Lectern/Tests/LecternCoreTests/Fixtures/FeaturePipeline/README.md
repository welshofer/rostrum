# Lectern feature pipeline fixtures

`authored-features.pptx` is generated by `FeaturePipelineFixture.make()` using
public Rostrum authoring APIs. Its four slides cover native and imported custom
table styles, merged cells, typed double/dashed borders, mixed text runs, an
owned four-quadrant PNG with cropping, notes, modern comments with a reply,
legacy comments, duplicated/imported slides, and sections.

Only the fixture factory normalizes its own generated annotation/section IDs and
annotation timestamps. No application pipeline code does this. Two fresh factory
invocations must produce identical bytes; inspect/export/reopen operations must
leave the saved source bytes untouched. The small PNG was independently encoded
using Python zlib and contains no third-party content or fonts.

`office-tables-v3.pptx` is an exact copy of the owned independent table fixture in
`Tests/RostrumTests/Fixtures/Conformance/python-tables-v3.pptx`. That fixture has
separate PowerPoint 16.113.3 slide and notes-page references. Its imported copy
exercises a real foreign package path through the Lectern pipeline. Provenance
and hashes are in `provenance.json`; no proprietary fonts have been copied.

The tests are file-backed LecternCore integration tests. They do not assert
native app behavior, Office acceptance of newly authored files, font rendering
accuracy, or whole-slide pixel equivalence. Native GUI testing is separate.

The authored fixture was regenerated on 2026-10-04 through the unchanged factory
for the new vertically centered cell default. Only `ppt/slides/slide1.xml` and
`ppt/slides/slide4.xml` changed: nine and two `a:tcPr` elements respectively now
carry `anchor="ctr"`. Removing those attributes reproduces the prior part bytes
exactly; the other 51 package parts and the foreign Office fixture are unchanged.
The pipeline test checks middle alignment after saving and reopening. This
fixture follows current authoring defaults; it is not a historical alignment oracle.
